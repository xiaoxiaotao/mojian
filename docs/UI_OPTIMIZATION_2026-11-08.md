# 800×480 墨水屏 UI 优化建议

日期：2026-11-08。对象：墨间 Mac / Android 共同渲染的 800×480 黑白红屏幕。
方法：用 `ui-ux-pro-max` 的 `design_recommend` / `design_search` / `design_review` 获取 E-Ink、单色、层级与可读性建议，再按 1-bit、三色、无背光、50cm 观看距离和局刷成本筛选。

## 结论

现有方向是对的：**纸张感、黑白高对比、左侧待办/右侧上下文、红色只做品牌**。不需要换风格，也不建议引入衬线、灰色、纹理或动效。

真正值得改的是三件事：

1. 底部行情区太密，14px 辅助字在 50cm 处偏小，五列占位符显得碎；
2. Mac 万年历重复显示月份，右侧 `2026 / 10` 与左侧 `2026年 10月` 信息重复；
3. 字号和 x 坐标有明显“逐处试出来”的痕迹，缺少一套固定的 8px 网格与字号令牌。

建议先做低风险的 Phase 1，再做网格/字体令牌，最后才动静态红色资源。

## 设计库结论与取舍

| 工具建议 | 是否采用 | 原因 |
| --- | --- | --- |
| E-Ink / Paper：高对比、纸张感、无动效、阅读优先 | ✅ | 与当前产品一致 |
| Minimalist Monochrome：纯黑/纯白、零圆角、无阴影 | ✅ | 1-bit 屏天然如此 |
| 粉色强调色 `#EC4899` | ❌ | 面板只有黑/白/红，红色已被品牌占用 |
| Playfair Display / Source Serif 正文 | ❌ | 衬线细笔画在 1-bit 二值化后容易断笔；继续思源黑体 + Inter |
| 纹理/噪点 | ❌ | 墨水屏没有灰阶，噪点会变成脏点 |
| 动效/过渡 | ❌ | 无意义，且会增加刷新 |
| 深色模式、触摸目标、bundle size | ❌ | 不适用于常驻显示面板 |

UX 检索命中的三条适用规则：正文对比度、不能只靠颜色传达状态、正文行高。当前黑/白对比已经最大；逾期用黑色加粗而不是红色，符合“不能只靠颜色”；待办 22px/截止 15px、卡片 20px 的行高也基本合适。

### 做得好的地方

- 时间是第一视觉锚点，52px 足够远读。
- 左/右分栏（约 500 / 250）稳定，扫视路径清楚。
- 2px 实线、零圆角、无阴影，符合纸张感。
- 红色只在品牌横带和右上角标签出现，没有被动态数据滥用。
- 思源黑体 Medium + Inter 数字的组合适合二值化；没有用细衬线。

## 设计令牌

### 字体

| 令牌 | 尺寸 | 用途 |
| --- | --- | --- |
| `micro` | 12 | 仅非必要信息；不用于需要阅读的正文 |
| `caption` | 14 | 可选注释；50cm 下已是下限 |
| `label` | 16 | 卡片标题、行情名称、日期辅助、红色标签下限 |
| `body` | 18 | 卡片正文、日程时间、一般正文 |
| `body-lg` | 20 | 卡片正文强调、日期 |
| `task` | 22 | 待办正文 |
| `section` | 23 | 区块标题 |
| `title` | 26 | 页面标题、气温 |
| `display` | 32 | 大数字、下班时间 |
| `clock` | 52 | 顶部时间 |
| `date-xl` | 84 | 下班大日期（小屏布局） |
| `date-hero` | 112 | 万年历大日期 |

保留 15px 仅作为“截止时间/标记”的过渡值，下一轮统一到 16px。

### 间距与网格

- 外边距 24px；内容区 24…776。
- 8px 基准：4 / 8 / 16 / 24 / 32 / 48。
- 两栏：左 24…528（504），右 544…776（232）；或右 552…776（224）。当前 526/550/572 需要一次性对齐。
- 分隔线 2px；区块间距 16/24；列表行高 46/58。

### 墨色

- 纸：`#FFFFFF`，墨：`#000000`；无灰阶、无网纹。
- 品牌红：沿用生成器的 `rgb(0.75,0.08,0.10)` ≈ `#BF141A`；只用于静态横带/品牌标签，不用于动态状态。
- 二值化阈值保持 168；不要为了“更柔和”引入灰。

## 分阶段改动

### Phase 1（低风险，建议先做）

1. 行情区：
   - 辅助字 14→15/16；删除“本机同步”一类重复标签；保留“行情可能延迟 · Open-Meteo”和时间。
   - 名称 16、价格 19、涨跌 16；占位只用一条 `—`，不要再画第二条短横。
   - 五列宽度仍 152，x 保持 24 + 152i；不改刷新区域。
2. Mac 万年历：
   - 右侧 `yyyy / MM` 改为“月历”（16px）或删除；左侧保留 `yyyy年 M月`。
3. 日期字号：
   - 日期 18→20；`休` 13→14；今天框保持 2px。
4. 文案：
   - 空行情统一为“行情待更新”；空天气统一为“天气待更新”。

Phase 1 不触碰红色静态资源、不改布局 ID、不改刷新波形；应用一次全刷即可。

### Phase 2（中等风险）

- 把 15/17/19/21/25/27/28/30/34 收敛到令牌；同步 Mac 与 Android。
- x 坐标统一到 8px 网格；重跑 `tools/generate_regions.py`，确认局刷窗口仍避开红带。
- 两栏宽度统一为 504/232 或 504/224；更新预览和区域测试。

### Phase 3（高风险）

- 静态红色资源：删除 9px `MOJIAN`、放大“墨间”、处理 3px 红点；需要同时重生成 8 套 Mac PNG、固件 `STATIC_ACCENTS` 和 Android 预览。
- 任何 `y=80…103` 内的改动都必须重新确认红带全白与局刷窗口不跨入。

## 约束与验证

- 不改 LUT、VCOM、极性、扫描模式；UI 优化只改排版与像素。
- 任何几何变化都需要一次明确全刷；不自动全刷、不因预览写屏。
- 预览只用虚构数据；不把真实待办/天气写进仓库图片。
- 1-bit 下不要用 1px 细线画图标/文字；最小描边 2px。
- 两端口径一致：Mac `ScreenRenderer` 与 Android `DeskRenderer` 的同一布局应使用同一字号/间距令牌。
- 改完跑 `sh tools/test.sh`，并用 `--render-previews` 生成虚构预览；实屏仍需用户确认。

## 建议

先做 Phase 1 的行情区 + Mac 月份去重 + 日期 20px。这三项改动小、可逆、视觉收益明确，且不需要动红色静态资源。Phase 2 的网格/字号令牌需要一次全刷和两端同步，建议单独一轮做。
