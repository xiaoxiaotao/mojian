# Android 0.4.1 界面设计

目标是让每天使用的动作靠近手指，让低频配置容易找到，并让每一步的结果清楚。

## 页面层级

主导航保留三项：工作台负责查看/处理待办，助手负责表达意图和确认提案，我的负责屏幕及助手配置。设置页分组为屏幕与助手；天气、股票、信息卡片分开编辑。子页记录来源，返回时恢复来源页面和滚动位置。导航状态支持活动重建。

## 操作优先级

工作台底部只突出新增，事项左侧完成、正文编辑、右侧更多。删除需确认，完成与删除提供短时撤销，长期恢复仍在记录中。预览和历史默认收起。助手输入区固定在内容滚动区之外，长对话不会把输入入口挤走；工具过程按需展开，变更以确认卡片呈现。

主要动作使用深绿实底，次要动作使用浅色，危险动作放入菜单后确认。字号、行距和留白统一，表单保留字段标签。点击区域以至少48dp为约束，参考 [Android官方无障碍指南](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)。状态同时通过文字表达，不能只依赖颜色。

## 反馈与输入

顶部状态入口显示连接、处理中、待同步或需处理，点开查看详情及同步入口。查询进度仅更新文字；设备后台检查不会在表单输入时替换整个页面。助手提交后显示最新消息，正常浏览时保留滚动位置；草稿和输入焦点在必要重绘时保留。键盘使用adjustResize，内容消费系统安全区。

## 显示与同步边界

布局选择仅暂存，明确确认应用后才更改配置并请求一次全刷。新增、完成、删除等普通操作继续使用原有同步队列及分区局刷。固定红色、其他内容区与多端冲突策略保留。

## 验证

2026-10-18：Debug APK在Mi 10 Pro上运行328项脱离窗口的原生布局断言，覆盖360dp宽、1.0/1.3字体及主要页面；通过后检查三页原生View渲染示例，修复底部标签对齐和状态入口显示。原有助手隔离测试、七种布局清字与同步检查重新验证。此类布局验证不覆盖真实输入法动画、系统手势与光学屏幕效果，按Android验收清单继续人工验收。

## Android0.8.0视觉整理

工作台以今日概览、待办清单和常用工具三层组织。待办集中于同一卡片，以分隔线区分；完成与更多使用线性图标，操作目标48dp。工具采用2×2入口，新增保持底部常驻。

纸白背景搭配墨绿重点，次要按钮改为白底描边；减少重复大色块，卡片标题16sp、正文15–16sp、辅助信息12–13sp。顶部连接状态视觉为小胶囊，但触控高度仍为48dp。底部选中背景仅包裹图标，标签保留。

“我的”依次组织设备、桌面与内容、日常安排、助手与提醒、设备与更多。所有原有目的页保留。助手使用墨绿发送气泡与白色回复，确认卡片内并排放置取消与确认；不会因为查看或切换页面而执行提案。

子页面从backStack最早根标签确定底部归属，所有子页面显示返回；回到入口保留原草稿和清单。UI仪器测试在未挂载原生View上覆盖320/360dp与1.0/1.3倍字体，2012项检查通过，新增工具点击/返回与助手设置上下文验证。仍需用户检验真实键盘、TalkBack和不同系统的观感。
