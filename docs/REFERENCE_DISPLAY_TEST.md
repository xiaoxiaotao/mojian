# 同型号参考驱动对照

这是诊断用的显式实验环境，默认构建保持原驱动。它用于比较同一面板在两套黑白局刷流程下的表现，不能仅靠HTTP成功确认光学效果。

```sh
../../pio run -d firmware -e esp32-l-gx-reference-ab
python3 tests/test_gx_reference.py
```

以上命令在本项目目录执行；编译不烧录。设备写入仍遵循应用分区更新、备份、身份核对及明确恢复显示基准的约定。

## 控制条件

- 两组保留相同布局、字体、红色保留带、区域规划、SPI引脚及10MHz频率；普通内容依旧按变化局刷。
- 显式全刷基准继续用原驱动，以保持起始绘图路径一致；参考组只切换本地HTTP/自主更新的黑白局刷初始化、窗口刷新和休眠。
- 不启用定时全刷，不添加测试待办，不修改用户清单；原Python轮询路径不属于参考组范围。
- 参考面板代码锁定GxEPD2 1.6.9提交，原文件哈希记录在`references/gxepd2-1.6.9/manifest.json`。仅基类底层读写接入项目安全保护及观测；不修改面板波形数组、VCOM参数或面板类方法。
- 参考库分别管理SPI事务，局刷不能再套原驱动的外层事务。分页写入不意味着逐页刷新；一个差分窗口仍只有一次DISPLAY_REFRESH。

## 安全与验证

隔离测试编译实际参考面板和基类，比较适配前后的正常初始化/局刷/休眠SPI记录；覆盖40行跨页写入、刷新后previous同步、PT_SCAN=0、红带和越界拒绝、超时后禁止继续传输以及固定故障关断。

另从实际`localPaint`提取函数编译集成夹具，验证无变化不传输、无嵌套SPI锁、错误时不确认显示成功、只有明确全刷才能恢复基准。原始参考库的BUSY超时不会自动接入本项目锁存，因此不能直接绕过安全适配用于用户设备。

健康接口中参考环境标识为：

```json
{
  "firmware_revision": "reference-stride-2026-11-08",
  "display_experiment": "gxepd2-1.6.9-reference",
  "display_reference_commit": "de82887e77a78528ea386e68bba2cb0291d2c319",
  "display_partial_spi_hz": 10000000
}
```

## 如何解释结果

运行实际时钟/天气属于“同布局与更新节奏”的初筛，不是逐帧重放的严格光学实验：数字、天气和环境温度可能变化，应记录累计局刷数、持续时间和同光照照片。

参考组在相近负载下干净而原组泛红，会支持继续定位原局刷生命周期差异；两组都泛红，仍需排查共用全刷基准、供电/RESE、SPI信号质量、面板批次和波形能力，不能直接认定整型号或单块面板损坏。

固件计数、影子帧和回执不是光学测量。参考组至少应与原组出现泛红时的运行时长/局刷负载相比较；没有实物反馈时，只能报告软件及协议验证通过。

## 本机阶段结果（2026-11-08）

原组与参考组均收到长时泛红/红条纹反馈。参考组初次全刷后用户确认干净，约10小时运行后的读取记录为677差分窗口、0显示超时；确切光学出现时间与条纹形态尚待核对。该实验没有证明解决问题，也没有隔离两组共用的全刷、供电和面板因素。

### 结果有效性修正

2026-11-08审查发现本项目适配器对previous窗口使用了错误的紧凑源API；故上述首次参考组并非正确旧帧输入的有效参考对照。候选reference-stride-2026-11-08改用完整源尺寸与源坐标，并以真实SPI旧帧字节验证；原始上游面板代码未变。此前正常流等价测试只证明安全适配基类没有改变相同调用流，不能证明调用方传入正确，现已补足此缺口。光学结果需部署后重新验证。
